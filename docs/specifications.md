# NablaSKK 仕様

利用者・組み込み側から見える NablaSKK の仕様。main で常に最新に保つ
(ADR 0001)。判断の経緯は `docs/adr/`(ADR 導入前は `docs/decisions.md`)を
参照する。ここに書いた内容と実装が食い違う場合は、どちらかを直す。

## 1. 位置づけ

- [AquaSKK](https://github.com/codefirst/aquaskk) の入力エンジンの Rust 移植と、
  それを使う macOS 入力メソッド(InputMethodKit)・設定アプリ・skkserv・skk-cli。
- エンジンの挙動は本家に合わせる。本家の受け入れテスト(400 ケース)と全一致する。
  本家と意図的に変えた点は `docs/decisions.md` と以後の ADR に記録する。
- 外部クレート依存なし。ライセンスは GPL-2.0-or-later。

## 2. 対応環境

- macOS 12 以降(入力メソッド・設定アプリ)。arm64 / x86_64 のユニバーサル版を配布。
- skkserv・skk-cli は macOS と Linux(x86_64)。

## 3. 入力

- 入力モード: ひらがな / カタカナ / 半角カナ / 英数(ASCII)/ 全角英数。
- キー操作は本家の `keymap.conf`(`data/keymap.conf`)に従う。主なもの:
  Ctrl-J でかなモード、`l` で英数、`L` で全角英数、`q` でひらがな⇔カタカナ、
  Ctrl-Q で半角カナ、`/` で abbrev、大文字で▽変換開始、スペース / `x` で候補送り・戻し、
  Enter / Ctrl-J で確定、Ctrl-G / Esc で取り消し、`X` で候補の削除、Ctrl-/ で確定の取り消し。
- ローマ字かな変換は本家の `kana-rule.conf`(`data/kana-rule.utf8.conf`)に従う。
- 本家の補助ルールを選べる(ADR 0003)。入力方式は標準 / AZIK(JIS 配列)/
  AZIK(US 配列)/ ACT から一つ。これと独立に、記号入力(yakumono-ippai、
  `z1` → ○ など)と旧かな(old-kana、`wi` → ゐ など)を足せる。ルールとキーマップ差分は
  本家の `data/` のファイル(EUC-JP)をアプリに同梱して使う。
  - ローマ字ルールの積み順: 組み込み → 入力方式 → 記号入力 → 旧かな → 句読点の設定 →
    ユーザー定義(`kana-rule.conf`)。後のものが勝つ。
  - キーマップの積み順: 組み込み → 入力方式の差分(AZIK は `azik.conf`、ACT は `act.conf`。
    既存の割り当てに重ねる)→ ユーザーの上書き(`keymap.conf`)。
  - AZIK ではひらがな⇔カタカナが keycode 0x21(JIS の `@`、US の `[`)、ACT では `\` に移る。
- 候補は最初の 4 件をインラインで ▼ 表示し、以降はマークテキスト内に
  `【a:候補 s:候補 …】(ページ/総ページ)` の形で 7 件ずつ並べる。a/s/d/f/j/k/l で選ぶ。
- 単語登録は再帰的に行える。登録中・見出し語入力中は Cmd-V でも貼り付けられる
  (改行は除く)。
- 別のアプリ(bundle id 単位)に切り替えると入力中の文字は確定され、モードは
  ひらがなに戻る。ただし、そのアプリで最後に英数モードだった場合は英数に戻す。
- IME が文字を出さずに処理したキーを、アプリが自分でも処理してしまう問題への
  対策がある(Ghostty はすべてのキー、Chromium 系は Ctrl 付きのキー)。

## 4. 辞書

### 4.1 dictionaries.conf

`~/Library/Application Support/NablaSKK/dictionaries.conf`。初回起動時に生成し、
AquaSKK の `SKK-JISYO.L` があればそれを使う。1 行に「タイプ 場所」、上から順に検索する。
行頭の `-` は無効、`#` はコメント。

| タイプ | 内容 | 場所 |
|---|---|---|
| 0 | SKK 辞書(EUC-JP / UTF-8 自動判別) | ファイルのパス |
| 1 | 自動ダウンロード | `host url 保存先パス` |
| 2 | skkserv(EUC-JP) | `host:port` |
| 4 | プログラム実行変換(today, now, `=式`, `jdate:` など) | 不要 |
| 5 | SKK 辞書(UTF-8 固定) | ファイルのパス |
| 6 | skkserv(UTF-8、NablaSKK 独自) | `host:port` |

- 自動判別は先頭行の `coding:` クッキー、なければ内容が UTF-8 として正しいかで決める。
- 設定アプリから追加した辞書は `dictionaries/` にコピーし、そのパスを書く。
  同名のファイルは上書きし、同じパスのエントリがあれば有効化するだけにする。
- 変更は即保存され、IME は次にアクティブになったとき(mtime の変化)に読み直す。

### 4.2 skkserv

`settings.conf` の `skkserv*` で設定したサーバーは、`dictionaries.conf` の
すべての辞書のあとに問い合わせる(ローカル辞書が優先)。

### 4.3 ユーザー辞書

`~/Library/Application Support/NablaSKK/skk-jisyo`(UTF-8、既存ファイルは
エンコーディングを保つ)。変換の確定で学習する。設定アプリで見出し語の検索・
追加・削除、候補の追加・並べ替え・注釈の編集ができる。IME 側に未保存の学習が
ある場合はそちらを優先する。

## 5. 設定ファイル

すべて `~/Library/Application Support/NablaSKK/` にあり、IME は mtime を見て
次にアクティブになったときに読み直す。

### 5.1 settings.conf(`key=value`)

| キー | 値 | 既定 | 内容 |
|---|---|---|---|
| `input_style` | `standard` / `azik` / `azik_us` / `act` | `standard` | 入力方式(補助ルール)。未知の値は `standard` |
| `yakumono_ippai` | `on` / `off` | `off` | 記号入力(SKK日本語入力FEP/Egg 互換) |
| `old_kana` | `on` / `off` | `off` | 旧かな(ゐ・ゑ・くゎ・ぐゎ) |
| `comma` | `japanese` / `fullwidth` | `japanese` | `,` を `、` / `，` にする |
| `period` | `japanese` / `fullwidth` | `japanese` | `.` を `。` / `．` にする |
| `suggest` | `on` / `off` | `off` | ▽入力中に、読みで始まる見出し語を一覧する(TAB で補完) |
| `suggest_count` | 1〜20 | 5 | 一覧する件数 |
| `completion_extended` | `on` / `off` | `on` | 補完・サジェストにシステム辞書も使う(off はユーザー辞書のみ) |
| `annotation` | `on` / `off` | `off` | 候補選択中に、辞書の注釈(`語;注釈` の注釈)をカーソルの下に出す |
| `skkserv` | `on` / `off` | `off` | skkserv を使う |
| `skkserv_host` | ホスト名 | `localhost` | |
| `skkserv_port` | 1〜65535 | 1178 | |
| `skkserv_encoding` | `euc-jp` / `utf-8` | `euc-jp` | |

### 5.2 keymap.conf

組み込みの keymap.conf に対する差分。1 行に「シンボル キー」(keymap.conf の書式)。
各行は、そのシンボルに割り当てられたキーをすべて外してから登録する。
設定アプリの「キー」ページで編集する。`SKK_PASTE` と内部属性は対象外。

### 5.3 kana-rule.conf

ユーザー定義のローマ字かなルール(例: `fj` → `、`)。1 行に
「入力,ひらがな,カタカナ,半角カナ」(UTF-8、`,` は `&comma;`、空白は `&space;`、
行頭の `#` は `&sharp;`)。組み込みルール → 句読点の設定 → このファイルの順に
重ねる。設定アプリの「ローマ字」ページで編集し、次のルールは保存しない
(比較は、組み込みに選んでいる補助ルールを重ねた表に対して行う)。

- 入力キーが空、空白・全角・大文字を含む、9 文字以上、`q` `l` `/` で始まる
- 組み込みや先に追加したルールと同一、または入力キーが衝突する
- 最後のキーで確定している既存ルールを延長する(`ka.` で `ka` が待つようになる)

## 6. 設定アプリ

入力メニューの「NablaSKK の設定...」で開く。左のサイドバーでページを選ぶ
(最後に開いたページを覚える)。

アクセシビリティ(ADR 0006): アイコンだけのボタンや名前のない部品には日本語の
読み上げラベルを付ける。注意・エラー・補足の文字は、ライト・ダークの両方で背景との
コントラスト比 4.5:1 以上の色にする。誤りは色とツールチップだけでなく文でも示す。
一覧の中の入力欄は 1 回のクリックで入力できる。

| ページ | 内容 |
|---|---|
| 辞書 | `dictionaries.conf` の編集(ファイルのドラッグ&ドロップで追加、有効 / 無効、行の先頭のつまみのドラッグか ↑↓ ボタンで並べ替え、名前・種類・場所。見つからないファイルは欄の下に文で示す) |
| ユーザー辞書 | ユーザー辞書の編集(候補はつまみのドラッグか ↑↓ ボタンで並べ替え) |
| skkserv | 有効 / ホスト / ポート / 文字コード |
| 入力 | 句読点、サジェスト、注釈 |
| ローマ字 | 入力方式(標準 / AZIK / ACT)・記号入力・旧かなの選択、ユーザー定義ルールの編集、組み込みと補助ルールの記号ルール(読み取り専用) |
| キー | キーバインドの変更 |

## 7. FFI(nablaskk-ffi)

C ABI。正は `crates/nablaskk-ffi/include/nablaskk.h`、Swift ラッパーは
`swift/SKKSession.swift`。

- 文字列は NUL 終端 UTF-8。Rust が返した `char*` は `skk_string_free` で解放する。
- セッションはスレッド非対応。同じスレッド(macOS では main thread)から呼ぶ。
- 機能: セッションの作成・破棄、辞書の追加・全消去、キー入力、確定文字列・
  マークテキスト・カーソル位置・入力モードの取得と設定、確定・取り消し・保存、
  ユーザー辞書の再読み込み、候補ウィンドウ・注釈・サジェストの取得、
  かなルールとキーマップの差し替え、エンジンオプション(`SKK_OPTION_*`)。

## 8. skkserv / skk-cli

- skkserv: skkserv プロトコル(既定ポート 1178、EUC-JP)の辞書サーバー。
  辞書のエンコーディングは自動判別(`-e` / `-u` で強制)。補完(コマンド `4`)に対応。
- skk-cli: ターミナルで SKK 入力を試すデモ。

## 9. 診断ログ

`debug-enabled` ファイルがあるときだけ `debug.log` に記録する。記録するのは
クライアントの bundle id・キーコード・修飾キー・処理結果と、アクティブ化の切り替え。
修飾なしの文字キーは内容を記録しない。

## 10. 開発とリリース

- 設計判断は実装の前に `docs/adr/` に ADR として書き、レビューを受けてから
  コミットする。コミット済みの ADR はステータスの行以外を変えない(adr-guard が
  git の pre-commit hook と CI で検査する。Claude Code の hook は利用者の全体の設定
  `~/.claude/settings.json` で入れる)。
- 作業はブランチで行い、main へは `--no-ff` でマージする。main を rebase しない。
- `v` で始まるタグを push すると CI がリリースの下書きを作る。タグ名に `-` を
  含む場合(`v1.1.0-rc` など)はプレリリースになる。リリースノートには追加・削除した
  ものを書く。
