# ADR 0005: 設定アプリのサイドバーで選択中の項目が強調されない不具合を直す

ステータス: 採択

## 文脈

設定アプリのサイドバー(`macos/Preferences/PreferencesApp.swift` の `RootView` と
`SidebarItem`)で、項目をクリックすると右側のページは切り替わるが、選択中の項目の
アクセント色の背景が切り替わらないことがある。作業者から報告があり、画面外の
ウィンドウにクリックを送る検証で再現した。

- どの順でクリックしても、最初の 1 回だけ強調が移り、2 回目以降は最初にクリックした
  項目に残る(例: 入力 → skkserv → 辞書 の順に押すと、強調は「入力」のまま)。
- 右側のページは毎回正しく切り替わる(`@AppStorage("selectedSettingsPane")` は更新
  されている)。
- `RootView.body` は毎回呼ばれるが、新しく選ばれた `SidebarItem` の `body` は呼ばれない。

`SidebarItem` は選択状態を `isSelected: Bool` で受け取り、クリック時の動作を
`action: () -> Void` のクロージャーで受け取っている。SwiftUI は子ビューを作り直す
前に前回の値と比べるが、クロージャーを含む構造体の比較は当てにならず、`isSelected`
の変化を見落として `body` を呼ばないことがある。最初の 1 回だけ更新されるのは、
クリックで `@State` の `hovering` が変わり、そのビューが描き直されるためと考えられる。
導入時(v1.0.0 以前、サイドバー化の直後)の検証では強調が正しく移っていたので、
SwiftUI の判断に依存して出たり出なかったりする。

## 実装すること

- `SidebarItem` が選択状態を `Bool` で受け取るのをやめ、選択中のページの値への
  `Binding<String>`(`@AppStorage` の `$selectedPane`)を受け取る。`body` の中で
  `selection == pane.rawValue` を計算し、クリックで `selection` を書き換える。
  `body` が選択中の値を直接読むので、SwiftUI が依存を追跡し、値が変わるたびに
  全行の `body` が呼ばれる。クロージャーは渡さない。
- 振る舞い(見た目・ホバー・最後に開いたページを覚えること)は変えない。

## 実装しないこと

- サイドバーを `List` や `NavigationSplitView` に戻すこと(前者はクリックで切り替わら
  なかった、後者は macOS 13 以降)。
- サイドバーの見た目の変更。
- ほかのページの変更。

## テスト設計

先に書いて失敗させてから実装する。

- 設定アプリのビューを画面外のウィンドウに置き、サイドバーにマウスのクリックを送る
  検証プログラム(`macos/Tests/PreferencesUITests/`、`macos/run-ui-tests.sh` で実行)を
  リポジトリに加える。保存先は一時ディレクトリに差し替え、利用者の設定に触れない。
  - いくつかの順(例: 入力 → skkserv → 辞書、キー → 入力、ローマ字 → 入力 → 辞書)で
    クリックし、毎回、選択中の項目だけがアクセント色の背景になっていることを、描画した
    画像の画素で確かめる。
  - 毎回、右側のページが切り替わっていること(`selectedSettingsPane` の値)。
- 修正前のコードでこの検証が失敗する(2 回目以降で強調が残る)ことを確かめてから直す。
- CI の macOS ジョブでも実行する(画面外のウィンドウなので、画面録画などの権限は要らない)。
- 既存の検証(`cargo test`、`sh macos/run-tests.sh`、`sh macos/build-app.sh` など)が
  すべて通ること。

## トレードオフ

- 画素で判定するので、色やレイアウトを変えると検証も直す必要がある。行の位置と
  アクセント色の判定は検証プログラムの中で一か所にまとめる。
- 画面外のウィンドウへのクリックは実機の操作と完全には同じではない。ただし今回の
  不具合は実機と同じ形で再現できたので、回帰の検出には足りる。
