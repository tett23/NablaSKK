# ADR 0008: テストの無い経路にリグレッションテストを足す

ステータス: 採択

## 文脈

v1.1.2 時点のテストは、Rust の単体テストと受け入れ 400 件、`swift/run-smoke-test.sh`、
`macos/run-tests.sh`(218 項目)、`macos/run-ui-tests.sh`(設定アプリ)である。設定アプリと
エンジンは厚いが、次の経路にはテストが無い。いずれもこれまでに不具合を直したか、変更が
入りやすい箇所である。

1. **IME 本体(`macos/Sources/SKKRustInputController.swift`)の判定**。テストから一度も
   参照されていない。
   - アプリごとの英数モードの記憶と復元。キーの記録時機と鍵の選び方を 2 回間違えて、
     3 回目で直した(v1.0.0 以前の 5573409)。
   - ローマ字ルールとキーマップの積み順(組み込み → 補助ルール → 句読点 → ユーザー定義、
     組み込み → 補助ルールの差分 → ユーザーの上書き。ADR 0003)。macOS テストは同じ順を
     テストの中に書き写して確かめているだけで、IME の実装が変わっても気付けない。
   - Command 付きのキーをアプリに渡すかどうか(Cmd-V は入力中だけ IME が受け取る)。
   - マークテキストの中のカーソル位置(エンジンの「末尾からの文字数」を UTF-16 の位置に
     直す)と、候補の行(`【a:漢字 s:感じ …】(1/2)`)の組み立て。絵文字の候補など、
     UTF-16 で 2 単位の文字で位置がずれうる。
2. **skkserv(`crates/skkserv`)**。テストが 0 件。辞書の文字コードの自動判別と `-e` / `-u`、
   補完(コマンド 4、本家に無かったもの)、通信の文字コード(EUC-JP)を確かめていない。
   エンジン側の `ProxyDictionary` のテストは、テストの中に作った簡易サーバーを相手にしており、
   本物の skkserv とは突き合わせていない。
3. **FFI の C ABI の約束事(`crates/nablaskk-ffi`)**。32 個の関数のうち、Rust 側のテストは
   1 件。Swift から多くを通しているが、NULL のセッションや NULL の文字列を渡しても落ちない
   こと、`skk_string_free(NULL)` が安全なことは確かめていない(ヘッダが約束している)。
4. **アプリの同梱ファイル(`macos/build-app.sh`)**。IME は補助ルールのファイル(ADR 0003)を、
   設定アプリは組み込みのルール表と補助ルールを Resources から読む。ビルドで入れ忘れても、
   その機能が黙って効かなくなるだけで、どのテストも失敗しない。

## 実装すること

### 1. IME 本体の判定を切り出してテストする

振る舞いは変えずに、次を純粋な型・関数として `macos/Sources/` から切り出し
(IME と `macos/run-tests.sh` の両方でコンパイルする)、IME はそれを呼ぶだけにする。

| 切り出すもの | 内容 |
|---|---|
| `ClientModeMemory` | アプリ(bundle id)ごとの最後の入力モードを、キーの処理のたびに記録し、アクティブ化のときに戻すべきモード(英数のときだけ英数)を返す |
| `EngineSetup.applyKanaRules` / `applyKeymap` | ローマ字ルールとキーマップを、決まった順に積み直す。補助ルールのディレクトリ・設定・ユーザー定義を引数で受け取る |
| `KeyRouting.passesToApplication` | Command 付きのキーをアプリに渡すか(Cmd-V / Ctrl-Y の貼り付けは入力中だけ受け取る) |
| `MarkedText.caret` / `MarkedText.candidateLine` | マークテキスト中のカーソルの UTF-16 位置、候補の行の文字列 |

`macos/run-tests.sh` のサブルールのテストは、書き写した積み順をやめて `EngineSetup` を使う。

### 2. skkserv の結合テスト

- `crates/skkserv/tests/` に、ビルドした skkserv を空いているポートで起動し、TCP で問い合わせる
  テストを置く(`CARGO_BIN_EXE_skkserv`)。辞書は一時ディレクトリに EUC-JP と UTF-8 の
  両方で作る。
- エンジンの `ProxyDictionary` を本物の skkserv につないで変換と補完ができることも確かめる
  (`nablaskk-core` の dev-dependency ではなく、skkserv の結合テストから `nablaskk-core` を使う。
  skkserv は既に `nablaskk-core` に依存している)。

### 3. FFI の約束事のテスト

- `crates/nablaskk-ffi` のテストに、すべての関数に NULL のセッションを渡しても落ちず、
  決まった値(0 / -1 / NULL)を返すこと、文字列の引数に NULL を渡しても落ちないこと、
  `skk_string_free(NULL)` が何もしないことを確かめるテストを足す。
- 返した文字列を `skk_string_free` で解放できること(二重解放はしない)も、代表的な関数で
  確かめる。

### 4. アプリの同梱ファイルの検査

- `macos/check-bundle.sh` を足す。`macos/dist/NablaSKK.app` に、実行ファイル、Info.plist、
  補助ルールの 7 ファイル(IME)、組み込みのルール表と補助ルールの 8 ファイル(設定アプリ)、
  設定アプリ本体があること、Info.plist の版番号が `Cargo.toml` と一致することを確かめる。
- CI の `build-macos` ジョブで、ビルドの直後に実行する。

## 実装しないこと

- 実際の InputMethodKit のクライアントを使った IME の結合テスト(テキストを入力して確定を
  確かめるもの)。macOS の入力ソースへの登録が要り、CI で動かせない。
- 補完ウィンドウ・注釈ウィンドウの見た目のテスト。
- skk-cli のテスト(端末の raw モードを使う対話用のデモ)。
- エンジン(`session.rs`・`editor.rs`)の単体テストの追加。受け入れ 400 件とセッションの
  結合テストで動きを固定している。
- 既存の振る舞いの変更(切り出しは振る舞いを変えない)。

## テスト設計

先に書いて失敗させてから実装する(切り出す型・関数は、テストを先に書くとコンパイルで失敗する)。

- `ClientModeMemory`(`sh macos/run-tests.sh`):
  - 英数で入力していたアプリに戻ると英数、ひらがなで離れたアプリはひらがな(何もしない)。
  - 次のアプリのアクティブ化が先に来て、前のアプリの記録がそのあとに来る順でも、前のアプリの
    英数が保たれる(5573409 で直した順序の問題)。
  - 同じアプリの別のウィンドウ(新しいコントローラ)でも記録が引き継がれる。
  - キーを一度も処理していないアプリは何もしない。
- `EngineSetup`(`sh macos/run-tests.sh`): 既存のサブルールのテスト(AZIK・ACT・記号入力・
  旧かな・句読点とユーザー定義の優先・キーマップの上書きの優先・標準に戻す)を、
  `EngineSetup` を通す形に書き換えて同じ結果になる。
- `KeyRouting`(`sh macos/run-tests.sh`): Cmd-C・Cmd-Q はアプリへ、入力中の Cmd-V・Ctrl-Y は
  IME へ、入力中でない Cmd-V はアプリへ、修飾なしのキーと Ctrl のキーは IME へ。
- `MarkedText`(`sh macos/run-tests.sh`): 「▽かんじ」の末尾・途中・先頭のカーソル位置、
  絵文字(サロゲートペア)を含む読みでの UTF-16 の位置、候補の行の文字列(選択中の印 ▶、
  ラベル、ページ番号)。
- skkserv(`cargo test -p skkserv`): EUC-JP の辞書と UTF-8 の辞書のそれぞれで、
  コマンド 1(見つかる / 見つからない)・2(版)・3(ホスト名)・4(補完)・0(切断)が
  本家のプロトコルどおりに応答する。`-e` / `-u` で辞書の文字コードを強制できる。
  `ProxyDictionary` から本物の skkserv で変換と補完ができる。
- FFI(`cargo test -p nablaskk-ffi`): NULL のセッション・NULL の文字列で全関数が落ちない。
  `skk_string_free(NULL)`。
- 同梱ファイル(`sh macos/check-bundle.sh`): 入れ忘れたファイルがあるとき、版番号が
  食い違うときに失敗することを、一時的にファイルを消した複製で確かめる。
- 既存のテストがすべて通ること。

## トレードオフ

- 切り出しのために IME 本体のコードを動かすので、振る舞いを変えてしまう危険がある。切り出す
  ものは純粋な計算に限り、IME はそれを呼ぶだけにする。切り出し後に実機で一通り入力して
  確かめる(英数モードの復元、補助ルール、貼り付け、候補の表示)。
- skkserv の結合テストは実際にポートを開くので、CI の環境によっては不安定になりうる。
  ポートは OS に空きを選ばせ、接続を何回か試してから失敗とする。
- 同梱ファイルの検査は、ファイルを足すたびにリストを直す必要がある。入れ忘れを検出する
  ことが目的なので、リストは `build-app.sh` とは別に持つ。
