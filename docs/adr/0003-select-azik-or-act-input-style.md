# ADR 0003: 設定アプリから補助ルール(AZIK・ACT・記号入力・旧かな)を選べるようにする

ステータス: 採択

## 文脈

本家 AquaSKK は、補助ルール(sub-rule)として拡張ローマ字入力の AZIK と ACT、
Egg 互換の記号入力(yakumono-ippai)、旧かな(old-kana)を持っている。設定画面で
選ぶと、次の順で読み込まれる(`SKKServer.mm` の `reloadComponents`)。

1. 組み込みの kana-rule.conf に、有効な補助ルールのローマ字ルールを重ねる
   (`SKKRomanKanaConverter::Patch`)。
2. 組み込みの keymap.conf に、補助ルールに対応するキーマップの差分を重ねる
   (`SKKPreProcessor::Patch`)。

NablaSKK の `data/` には本家と同じファイルがそろっている(EUC-JP)。

| ファイル | 内容 |
|---|---|
| `azik.rule` | AZIK(JIS 配列用)のローマ字ルール。`q` → ん、`;` → っ、`:` → ー、`kz` → かん など |
| `azik_us.rule` | AZIK(US 配列用)。`:` → っ、`'` → ー など、記号の位置が US 配列向け |
| `act.rule` | ACT。`q` → おん、`x` → いん、`;` → あん、`'` → っ など |
| `azik.conf` | AZIK のキーマップ差分。`q` などの既存の割り当てを外し、ひらがな⇔カタカナを keycode 0x21(JIS の `@`、US の `[` の位置)に移す。Shift+keycode 0x29(`;` の位置)を大文字扱い(▽開始)にする |
| `act.conf` | ACT のキーマップ差分。ひらがな⇔カタカナを `\` に移す |
| `yakumono-ippai.rule` | 記号入力(39 件)。`z1` → ○、`z!` → ●、`z(` → 【 など。組み込みの `z-` `z[` `z]` `z,` `z/` を同じ記号で上書きする |
| `old-kana.rule` | 旧かな(4 件)。`wi` → ゐ、`we` → ゑ、`kwa` → くゎ、`gwa` → ぐゎ。組み込みの `wi`(うぃ)・`we`(うぇ)を置き換える |

本家での読み込み順は sub-rule.desc の並び(句読点 → AZIK → AZIK(US)→ ACT →
記号入力 → 旧かな)で、後のものが勝つ。記号入力・旧かなは AZIK とは重ならず、
ACT とは重なる(記号入力は `z;` `z,` など 7 件、旧かなは `wi` `we`)。

しかし、どれも読み込む経路が無い。

- エンジンの組み込みは `kana-rule.utf8.conf` と `keymap.conf` だけ。
- IME は句読点の 2 行(comma.rule / period.rule 相当)を Swift に埋め込んで重ねているだけ。
- キーマップを変える FFI は `skk_session_override_keymap` だけで、これは各行の
  シンボルの割り当てをすべて外してから入れ直す(ADR 導入前の「キー」ページ用)。
  AZIK の差分には `UpperCases Q||shift::keycode::29` のような「既存に追加する」行があり、
  入れ直す方式で適用すると A〜Z の大文字がすべて効かなくなる。本家と同じく、重ねて
  適用する方式が要る。

## 実装すること

### エンジン・FFI

- `skk_session_patch_keymap(session, text)` を追加する。keymap.conf 書式のテキストを
  `Keymap::load`(既存への追加、`Not` で始まる行は属性を外す)で重ねる。
  `nablaskk.h` と `SKKSession.swift`(`patchKeymap(_:)`)も同時に更新する。
- 補助ルールの中身はエンジンに埋め込まない(IME がファイルを読む)。エンジンの
  ローマ字かな変換・キーマップの処理は変えない。

### 補助ルールの設定

- `settings.conf` に `input_style` を追加する(入力方式。一つを選ぶ)。

  | 値 | 内容 | ローマ字ルール | キーマップ差分 |
  |---|---|---|---|
  | `standard`(既定) | 標準のローマ字入力 | なし | なし |
  | `azik` | AZIK(JIS 配列用) | `azik.rule` | `azik.conf` |
  | `azik_us` | AZIK(US 配列用) | `azik_us.rule` | `azik.conf` |
  | `act` | ACT | `act.rule` | `act.conf` |

  未知の値は `standard` とみなす。三つは同時に使えない(本家では個別のチェック
  ボックスだが、ルールが重なり合うので一つを選ぶ形にする)。既定は本家と同じく
  補助ルールなし。
- `settings.conf` に `yakumono_ippai`(`on` / `off`、既定 `off`)と `old_kana`
  (`on` / `off`、既定 `off`)を追加する。入力方式と独立に、組み合わせて使える
  (キーマップ差分は無い)。

### 読み込み順(IME)

- ローマ字ルール: 組み込み → 入力方式のルール → 記号入力 → 旧かな →
  句読点(`comma` / `period`)→ ユーザー定義(`kana-rule.conf`)。
  入力方式・記号入力・旧かなの間は本家と同じ順(ACT と記号入力を併用すると
  `z;` は ACT の「ざん」ではなく記号入力の「゛」になる)。句読点は本家では先頭だが、
  句読点の設定とユーザー定義は利用者が明示的に選んだものなので、最後に重ねて優先する。
- キーマップ: 組み込み → 入力方式の差分(`skk_session_patch_keymap`)→
  ユーザーの上書き(`keymap.conf`、`skk_session_override_keymap`)。
- `settings.conf` の `input_style` が変わったら、ローマ字ルールとキーマップの両方を
  積み直す(今は `settings.conf` の変更でローマ字ルールだけを積み直している)。
  `yakumono_ippai` / `old_kana` の変更ではローマ字ルールを積み直す。
- ルールとキーマップ差分のファイル(EUC-JP)は IME の Resources に同梱し、
  EUC-JP として読む。

### 設定アプリ

- 「ローマ字」ページの先頭に「入力方式」のラジオボタン(標準 / AZIK(JIS 配列)/
  AZIK(US 配列)/ ACT)を置く。それぞれの主な違い(例: AZIK は `q` が「ん」、
  ひらがな⇔カタカナが `@` キー)を一行で添える。
- その下に「記号入力(SKK日本語入力FEP/Egg 互換)を使う」「旧かな(ゐ・ゑ・くゎ・ぐゎ)
  を使う」のチェックボックスを置く。
- 「ローマ字」ページのユーザー定義ルールの衝突判定(同一・入力キーの衝突・既存
  ルールの延長)に、選んでいる補助ルールも含める。比較対象のルール表は
  設定アプリにも同梱する。
- 「組み込みの記号のルール」の一覧は、補助ルールも重ねた実際の表から作る。

### ドキュメント

- `docs/specifications.md`(入力・設定ファイル・設定アプリの節)と README に、
  入力方式の選び方と読み込み順を書く。

## 実装しないこと

- 句読点(comma.rule / period.rule)の扱いの変更。今の `settings.conf` の
  `comma` / `period` のまま。
- 利用者が任意の補助ルールファイルを追加する機能(本家は Application Support の
  ファイルも読む)。
- 「キー」ページの既定値の表示を入力方式に合わせること。「キー」ページは組み込みの
  keymap.conf を既定として表示し続ける(AZIK でひらがな⇔カタカナが `@` に移っても、
  「キー」ページの既定は `q` のまま)。ページに注記を出す。
- AZIK・ACT のルールファイルの中身の変更(本家のものをそのまま使う)。
- エンジンのローマ字かな変換・キーマップ処理の変更。

## テスト設計

先に書いて失敗させてから実装する。

### Rust(`cargo test`)

- `Keymap::load` で `data/azik.conf` を重ねると、
  - 文字 `q` が ToggleKana でなくなり(InputChars のみ)、keycode 0x21 が ToggleKana になる。
  - Shift+keycode 0x29 に UpperCases が付き、A〜Z の UpperCases は残る。
  - Ctrl-J など、差分に無い割り当ては変わらない。
- `data/act.conf` を重ねると、`\` が ToggleKana、`q` は ToggleKana でなくなる。
- FFI: `skk_session_patch_keymap` で `azik.conf` を重ねたあと `skk_session_reset_keymap`
  で元に戻る。

### macOS テスト(`sh macos/run-tests.sh`、エンジン経由の入力)

- `InputSettings` の `input_style` の読み書き(4 値、未知の値は standard、往復)。
- AZIK(JIS): 組み込み + `azik.rule` + `azik.conf` を重ねたセッションで、
  `kz` → かん、`q` → ん、`;` → っ、`ss` → せい。`@` キー(keycode 0x21)で
  カタカナに切り替わる。
- AZIK(US): `:` → っ、`'` → ー。
- ACT: `q` → おん、`x` → いん、`\` でカタカナに切り替わる。
- 標準: `q` でカタカナに切り替わり、`kz` は AZIK の かん にならない。
- 読み込み順: AZIK + 句読点の「，」設定では `,` が「，」になる。AZIK のルールと
  衝突するユーザー定義ルールは衝突として保存されない。ユーザー定義ルールは
  入力方式より優先される(衝突しない範囲で)。キーマップのユーザー上書きは
  入力方式の差分より優先される。
- 入力方式を standard に戻すと、ローマ字ルールとキーマップが標準に戻る。
- 記号入力: `z1` → ○、`z(` → 【、`z,` → ‥(組み込みと同じ)。off では `z1` が記号にならない。
- 旧かな: `wi` → ゐ、`we` → ゑ、`kwa` → くゎ。off では `wi` → うぃ。
- 併用: AZIK + 記号入力 + 旧かなで、それぞれのルールが効く。ACT + 記号入力では
  `z;` が「゛」になる(記号入力が後)。
- `yakumono_ippai` / `old_kana` の読み書き(既定 off、往復)。

### 実機での確認(自動化できないもの)

- 設定アプリで入力方式を切り替え、次にアプリで入力を始めたときに反映されること。
- AZIK(JIS)で `@` キー、ACT で `\` キーによるひらがな⇔カタカナの切り替え
  (キーボード配列に依存するため実機で確かめる)。

## トレードオフ

- 三つを排他にしたので、本家のように AZIK と ACT を同時に有効にすることはできない。
  両者はキーの意味が重なり合い、同時に使うと結果がファイルの読み込み順に依存するので、
  一つを選ぶ形のほうが分かりやすい。
- 句読点とユーザー定義を入力方式より後に重ねるため、本家と読み込み順が異なる。
  利用者が明示的に設定したものを優先するという方針を取った。
- 「キー」ページの既定表示が入力方式に追従しないので、AZIK・ACT を選ぶと実際の
  キーと表示が食い違う。注記で補い、追従させるかは利用状況を見て別途判断する。
- 記号入力・旧かなは入力方式と組み合わせられるが、ACT との併用では一部のキーの意味が
  記号入力・旧かなのほうに変わる。本家と同じ順なので本家の利用者には同じ結果になる。
  設定画面で ACT と併用したときに注記を出す。
- ルールファイルを IME と設定アプリの両方に同梱するので、アプリのサイズが少し増える
  (ファイルは合わせて約 34KB で、IME と設定アプリの 2 か所で約 70KB)。
