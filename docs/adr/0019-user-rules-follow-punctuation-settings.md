# ADR 0019: ユーザー定義のルールの句読点を、句読点の設定に合わせる

ステータス: 採択

## 文脈

設定アプリの「入力」ページには、読点(`、` / `，`)と句点(`。` / `．`)を切り替える設定がある
(`settings.conf` の `comma` と `period`)。今の実装は、設定が全角のとき、`,` と `.` のルール
(`InputSettings.commaRule`、`periodRule`)を組み込みのルールに重ねるだけである。

作業者は、ユーザー定義のルールで `fj` → `、`、`fk` → `。` を使っている。この出力は書いたとおりの
文字のままなので、句読点の設定を全角にしても `fj` では `、` が入る。作業者は、これらのルールも
設定に倣って `，` `．` になることを求めている。

## 実装すること

- ユーザー定義のルール(`kana-rule.conf`)をエンジンに渡すとき(`EngineSetup.applyKanaRules`)、
  句読点の設定に合わせて出力を置き換える。
  - 読点が全角(`comma=fullwidth`)のとき: ひらがな・カタカナの出力の `、` を `，` に、
    半角カナの出力の `､` を `,` にする。
  - 句点が全角(`period=fullwidth`)のとき: ひらがな・カタカナの出力の `。` を `．` に、
    半角カナの出力の `｡` を `.` にする。
  - 置き換えの対応は、今の `commaRule` と `periodRule`(`,` と `.` を全角にするルール)の
    各モードの出力と同じにする。
  - 出力の中のどこにあっても置き換える(`ds` → `です。` なら `です．`)。
- `kana-rule.conf` のファイルそのものは書き換えない。ファイルにも設定アプリの表示にも、
  書いたとおりの `、` `。` が残り、エンジンに渡すときだけ置き換える。設定を戻せば、
  そのまま `、` `。` に戻る。
- 設定アプリの「ローマ字」ページに、出力の `、` `。` は「入力」ページの句読点の設定に
  合わせて入ることを書く。
- 仕様書(5.1 節の `comma` と `period`、5.3 節)と README(日本語と英語)に書く。

## 実装しないこと

- 組み込みのルールや補助ルール(AZIK、ACT、記号入力など)の出力の `、` `。` を置き換えること。
  今の `,` と `.` のルールだけが設定に従う扱いは変えない。
- 辞書の候補や、単語登録で入れた文字の句読点を置き換えること。
- 全角以外の句読点(`，` を `、` に戻すなど、逆向きの置き換え)。
- 句読点ごとに、ルールで設定に倣うかどうかを選べるようにすること。

## テスト設計

先に書いて失敗させてから実装する。

- `sh macos/run-tests.sh`(`EngineSetup` と `KanaRuleSettings`):
  - 読点が全角のとき、`fj` → `、` のルールで、ひらがなモードでは `，`、カタカナモードでは `，`、
    半角カナモードでは `,` が入ること。句点が全角のとき、`fk` → `。` で `．` `．` `.` が入ること。
  - 片方だけ全角のとき、もう片方は置き換えないこと(読点だけ全角なら `fk` は `。`)。
  - どちらも既定(和文)のときは、今までどおり `、` `。` が入ること。
  - 出力の途中の句読点も置き換えること(`ds` → `です。` で `です．`)。
  - `kana-rule.conf` に書き出す内容は、設定によらず書いたとおりであること。
- 既存の検証(`cargo test`、`cargo clippy --all-targets`、`sh swift/run-smoke-test.sh`、
  `sh macos/run-tests.sh`、`sh macos/run-ui-tests.sh`、`sh macos/build-app.sh`、
  `sh macos/check-bundle.sh`)が通ること。
- 実機で作業者が確かめる: 「入力」ページで読点と句点を全角にし、`fj` `fk` で `，` `．` が入ること。
  戻すと `、` `。` に戻ること。

## トレードオフ

- 置き換えはエンジンに渡すときに行うので、ファイルには書いたとおりの文字が残る。設定を
  切り替えるたびにファイルを書き換える必要がない。その代わり、ファイルの中身と実際に入る文字が
  違うことがあるので、そのことを設定アプリに書く。
- ユーザー定義のルールの `、` `。` は必ず設定に従う。和文の `、` を出したいルールを全角の設定と
  並べて使うことはできなくなる。要るとわかったら、ルールごとに選べるようにする ADR を書く。
- 組み込みや補助ルールの `、` `。` は置き換えないので、それらとユーザー定義のルールとで扱いが
  分かれる。今の設定が `,` と `.` のキーについての設定として書かれていることに合わせた。
