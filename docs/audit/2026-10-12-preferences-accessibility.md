# 設定アプリ(NablaSKK Preferences)のアクセシビリティ監査

- 実施日: 2026-10-12
- 対象: `main` の `48e1450`(v1.1.0 と同じ設定アプリのソース)、`macos/Preferences/` の全ページ
  (辞書・ユーザー辞書・skkserv・入力・ローマ字・キー)とサイドバー
- 基準: WCAG 2.2 の達成基準(レベル A / AA)を目安にし、macOS のアクセシビリティ
  (VoiceOver・キーボード操作)の観点を加えた
- この記録はコミット後に変更しない。指摘への対応は ADR を書いて行い、再監査は別の
  ファイルにする。

## 方法と限界

| 方法 | 内容 |
|---|---|
| コードの点検 | 全ページの SwiftUI のコードを読み、ラベル・色・ツールチップ・操作方法を確認した |
| コントラストの計算 | 使っている文字色と背景色の組み合わせを、macOS のライト / ダークの外観で解決し、WCAG の式でコントラスト比を計算した。半透明の色は背景に合成してから計算した |
| 操作の確認 | 画面外のウィンドウに設定アプリを置き、マウスのクリックを送って、どの部品にフォーカスが入るかを調べた。保存先は一時ディレクトリにした |

次は実施していない。結果に含まれないので、別途確認が要る。

- VoiceOver での実際の読み上げ(画面録画の権限がない環境で行ったため)。読み上げに関する
  指摘はコードからの推定である。
- 「フルキーボードアクセス」を有効にした状態での Tab 移動の順序。
- アクセシビリティインスペクタでの要素ツリーの確認。

## 結果の要約

| 区分 | 件数 | 主なもの |
|---|---|---|
| 高 | 5 | アイコンだけのボタンに日本語のラベルがない、辞書の有効化チェックボックスに名前がない、橙の注意文のコントラスト不足(ライト 2.31:1)、辞書の場所とキーの誤りを色とツールチップだけで示している |
| 中 | 7 | 入力欄の名前がプレースホルダー頼み、補足文のコントラスト不足(ライト 3.95:1)、赤のエラー文のコントラスト不足、読み取り専用の欄のコントラスト不足、一覧表の中の入力欄に 1 回目のクリックでフォーカスが入らない、サイドバーが一覧として読まれない |
| 低 | 4 | 装飾のアイコンが読み上げ対象になりうる、選択中のサイドバーの文字とアクセント色の比、無効化した辞書の行の薄さ、10pt の文字の多用 |

## 指摘

### 1. 読み上げ(VoiceOver)

**A-1(高)アイコンだけのボタンに日本語のラベルがない** — WCAG 1.1.1、4.1.2

次の 13 個のボタンは SF Symbols のアイコンだけで、`accessibilityLabel` を付けていない。
`.help` はツールチップ(とヘルプ)であってラベルではないので、VoiceOver はアイコン由来の
名前(英語の記号名など)か、何も読まない可能性が高い。

| ページ | ボタン | `.help` |
|---|---|---|
| 辞書 | 追加(`plus`、メニュー)、削除(`minus`)、上へ(`arrow.up`)、下へ(`arrow.down`) | なし |
| ユーザー辞書 | 見出し語の追加・削除(`plus` / `minus`)、候補の追加・削除(`plus` / `minus`)、候補を上へ・下へ(`arrow.up` / `arrow.down`) | 追加・削除のみあり |
| キー | デフォルトに戻す(`arrow.uturn.backward`) | あり |
| ローマ字 | ルールの削除(`trash`) | あり |

場所: `PreferencesApp.swift` 351〜367 行、`UserDictionaryView.swift` 175〜180・303〜320 行、
`KeymapSettingsView.swift` 103 行、`KanaRuleSettingsView.swift` 231 行。

**A-2(高)辞書の有効化チェックボックスと種類のポップアップに名前がない** — WCAG 1.3.1、4.1.2

「辞書」ページの各行の `Toggle("", isOn:)` と `Picker("", ...)` は `.labelsHidden()` で、
名前が空である。VoiceOver では「チェックボックス」「ポップアップボタン」とだけ読まれ、
どの辞書の何を切り替えるのかが分からない。行の辞書名(`entry.name`)は隣のテキストに
あるだけで、部品とは結び付いていない。
場所: `PreferencesApp.swift` 421〜436 行。

**A-3(中)入力欄の名前がプレースホルダー頼み** — WCAG 1.3.1、2.4.6、3.3.2

- 「ローマ字」ページの各行の入力欄は `TextField("fj", ...)` と `TextField("、", ...)` で、
  例のための文字がそのまま欄の名前になる。どの行でも「fj」「、」と読まれ、入力キーの欄か
  出力の欄か、何行目かが分からない。
- 「キー」ページの欄は `TextField(action.defaultKeys, ...)` で、名前が既定のキーの書式
  (`ctrl::j` など)になる。操作名(「かなモードへ」)は隣のテキストにあるだけ。
- 列の見出し(「名前」「種類」「場所」「入力キー」「出力」「操作」「キー」)は見た目の
  テキストで、各欄とは結び付いていない。

**A-4(中)サイドバーが一覧として読まれない**

サイドバーはボタンを縦に並べた独自の部品で([ADR 0005](../adr/0005-fix-sidebar-selection-highlight.md) の経緯で `List` をやめた)、
「6 項目の一覧」のような構造が伝わらない。選択中の項目には `.isSelected` の特性を
付けており(良い点)、各項目のアイコンと文字はまとめて読まれる。矢印キーで項目を
移動できるかは未確認。

**A-5(低)装飾のアイコンが読み上げ対象になりうる**

「ローマ字」ページの各行の矢印(`arrow.right`)、ユーザー辞書の検索欄の虫眼鏡、空の
状態の本のアイコンは意味を持たない装飾だが、`accessibilityHidden` を付けていない。

### 2. 色とコントラスト

文字色と背景色のコントラスト比(WCAG 1.4.3、通常の文字は 4.5:1 以上が AA)。

| 組み合わせ | 主な使い場所 | ライト | ダーク |
|---|---|---|---|
| 本文(`labelColor`)/ ウィンドウ背景 | 全般 | 14.94:1 | 12.23:1 |
| 補足(`secondaryLabelColor`)/ ウィンドウ・一覧の背景 | 説明文(10pt の caption が中心、25 か所以上) | **3.95:1** | 5.89:1 |
| 注意(`systemOrange`)/ 背景 | ローマ字ページの注記、組み込みルールの置き換え注意など | **2.31:1** | 7.47:1 |
| エラー(`systemRed`)/ ウィンドウ背景 | 保存できない、ポート番号、キーの誤り | **3.57:1** | 4.86:1 |
| エラー(`systemRed`)/ 赤い行の背景(赤 8%) | ローマ字ページの衝突・不正の理由 | **3.21:1** | **4.48:1** |
| 白 / アクセント色 | 選択中のサイドバーの項目(13pt) | **4.02:1** | **4.02:1** |
| 無効の欄の文字 / 欄の背景 | ローマ字ページの組み込みの記号ルール(読ませたい内容) | **1.82:1** | **2.26:1** |
| 本文 × 不透明度 0.5 / ウィンドウ背景 | 無効化した辞書の行 | **3.07:1** | **4.07:1** |
| 本文 / アクセント色 15% | ユーザー辞書の「送り」バッジ | 12.83:1 | 10.63:1 |

アクセント色は監査した環境の設定(既定の青)での値で、利用者の設定によって変わる。

**C-1(高)橙の注意文がライトモードで 2.31:1** — WCAG 1.4.3

ACT と記号入力・旧かなの併用時の注記、組み込みルールの置き換えの注意など、読んで
ほしい内容に使っている。

**C-2(中)補足文がライトモードで 3.95:1** — WCAG 1.4.3

システム標準の補足色だが、10pt の小さな文字(`.caption`)に多用しているため、読みにくい。
各設定の意味を説明する文が多く含まれる。

**C-3(中)赤のエラー文が 3.57:1(赤い行の上では 3.21:1)** — WCAG 1.4.3

ローマ字ページでは赤枠と背景色・文言を併用しているので、内容は伝わるが、文字自体は
読みにくい。

**C-4(中)読み取り専用の組み込みルールを無効の入力欄で表示している** — WCAG 1.4.3、4.1.2

「ローマ字」ページの組み込みの記号ルールは、変更できないことを示すために無効にした
入力欄で表示しており、文字のコントラストが 1.82:1 しかない。無効の部品はコントラストの
基準の対象外だが、ここは利用者に読ませたい内容である。VoiceOver では「無効の
テキストフィールド」として読まれ、内容を表すラベルもない。
場所: `KanaRuleSettingsView.swift` の `BuiltinKanaRuleRow`。

**C-5(低)選択中のサイドバーの項目が 4.02:1**

白い 13pt の文字とアクセント色(既定の青)。わずかに AA に届かない。アクセント色を
変えている利用者では値が変わる。

**C-6(低)無効化した辞書の行が不透明度 0.5 で 3.07:1** — WCAG 1.4.3

無効であることはチェックボックスでも分かるが、行全体が読みにくくなる。

### 3. 色やツールチップだけで伝えている情報

**C-7(高)辞書の場所が見つからないことを、文字の色とツールチップだけで示している** — WCAG 1.4.1、1.3.3

「辞書」ページで辞書ファイルが見つからないと、場所の欄の文字が赤くなるだけで、理由
(「ファイルが見つかりません」)はツールチップにしか出ない。色の区別が難しい利用者や
VoiceOver の利用者には伝わらない。
場所: `PreferencesApp.swift` 440〜443 行。

**C-8(高)キーの書き方の誤りを、文字の色とツールチップだけで示している** — WCAG 1.4.1、3.3.1

「キー」ページで書き方が正しくないと、欄の文字が赤くなるだけで、理由はツールチップに
しか出ない。同じ種類の誤りを、「ローマ字」ページ(理由を文で表示)や「入力」ページの
カーソル移動の欄(以前の実装)では文で示しており、ページによって扱いが違う。
場所: `KeymapSettingsView.swift` 94〜97 行。

**C-9(低)補足の情報がツールチップだけにある**

辞書の有効 / 無効の意味(「チェックを外すと検索対象から外れます」)、途中で省略された
辞書名の全体、キーの既定値はツールチップだけにある。マウスを載せない操作では分からない。

### 4. 操作

**O-1(中)一覧表の中の入力欄に、1 回目のクリックでフォーカスが入らない**

「辞書」ページの場所の欄をクリックすると、1 回目は一覧表(行の選択)がフォーカスを
取り、2 回目で欄に入った(画面外のウィンドウにクリックを送って確認)。「ローマ字」ページで
同じ作り(選択できる `List` の中の入力欄)をやめて直した問題と同じである。
「ユーザー辞書」ページの候補の欄も同じ作りで、同様と推定する(未確認)。

**O-2(良い点)辞書の追加にドラッグ&ドロップ以外の方法がある**

「+」メニューの「辞書ファイルを選択...」で、ドラッグを使わずに追加できる(WCAG 2.5.7)。

**O-3(未確認)キーボードだけでの操作**

フルキーボードアクセスでの Tab 移動の順序、サイドバーの矢印キーでの移動、
「ローマ字」ページの「ルールを追加」後の入力欄へのフォーカス(コード上は自動で移る)
は確認していない。

### 5. 文字の大きさ

**T-1(低)説明文の多くが 10pt**

説明文・補足に `.caption`(10pt)と `.caption2`(10pt)を多く使っている。macOS には
iOS のような動的な文字サイズがなく、利用者が大きくできない。

## 良い点

- サイドバーの選択中の項目に、色に加えて `.isSelected` の特性を付けている。
- 「ローマ字」ページの衝突・不正は、赤枠と背景色に加えて理由を文で示している。
- 設定の多くは標準の部品(チェックボックス、ラジオボタン、ステッパー)で、文字の
  ラベルを持っている。
- ダークモードでは、ほとんどの組み合わせが AA を満たす。

## 対応の優先度(提案)

対応は ADR を書いてから行う。この監査では変更していない。

1. アイコンだけのボタンへの日本語ラベル(A-1)、辞書の有効化・種類に辞書名を含む
   ラベル(A-2)、装飾のアイコンを読み上げから外す(A-5)。
2. 色とツールチップだけの情報を文でも示す(C-7、C-8)。「ローマ字」ページと同じ表示に
   そろえる。
3. 注意・エラーの色を、ライトモードでも 4.5:1 を満たす色にする(C-1、C-3)。補足文の
   大きさか色を見直す(C-2、T-1)。
4. 読み取り専用のルールを無効の欄ではなく文字で表示する(C-4)。
5. 一覧表の中の入力欄(O-1)を「ローマ字」ページと同じ作りにする。
6. 入力欄に意味のあるラベルを付ける(A-3)。
7. VoiceOver とフルキーボードアクセスで実機確認する(O-3 と、読み上げの指摘の検証)。
